# Audit — 2026-10-24

Scope: what the current source in this package does, plus the live qualification evidence that
exists today. Claims are limited to observed behavior; parent review adds full-suite evidence
after this run (see the launcher report, not a count invented here).

## Implemented in current source

- **Events and usage.** Attempt events are parsed from the worker's own JSONL; token and timing
  fields are recorded only when measured, with `complete`/`partial` availability, and cached
  tokens stay separate from uncached ones. A `turn.completed` record is the terminal signal;
  documented terminal failures (`turn.failed`, error events) end an attempt unsuccessfully even
  when the process exits `0`, and only the last executed attempt decides the verdict so a clean
  retry can recover a failed turn.
- **Retry semantics.** Tool observations deduplicate across attempts instead of resetting: a
  tool call observed in attempt 1 survives an attempt 2 that called nothing, and only an explicit
  `mcp_tool_call` lifecycle event naming a configured server and an enabled tool counts.
- **Task-specific permissions and tool manifest.** `--tool-config` is a separate schema-1
  manifest per job (`examples/tool-config.json`); nothing is inherited from the plugin or app
  configuration. It declares `required_commands`, per-server `command`/`args`/`env_vars`, and a
  non-empty `enabled_tools` allowlist. Unknown keys, a missing allowlist, or both transports at
  once are refused.
- **Credentials and preflight.** The manifest names environment variables only — never values —
  and a selected value must be at least 4 characters so it can be redacted. Values never reach
  argv, the prompt, the report, or the logs. A missing `required_commands` executable, a server
  that cannot be probed, or a named credential that is unset blocks the job **before** the
  worker starts. Model routing is pinned by preflight: canonical alias, fallback disabled, alias
  present in the served list; a different served model is `model_mismatch`, never a model switch.
- **Evidence states.** `configured` (named in the manifest), `probed` (metadata probe
  initialized the server and listed tools), `observed` (explicit lifecycle event in that job's
  own stdout). The probe starts no model turn and is not the live worker backend.
- **Resource bounds.** One shared deadline covers lock wait, preflight, probe, every attempt, all
  verification commands, the audit and report writing, and it is re-checked at the boundary before
  each phase, so a phase that no longer fits in what is left is refused instead of started and
  truncated. Worker stdout/stderr capture is capped (`CAPTURE_LIMIT_BYTES`) and the worker and
  verifier processes are killed with their whole group at their own caps, so per-process execution
  and output are bounded. Verification gets an explicit reserve — 20% of the job budget, bounded
  5–60 s, and 0 s with `--no-verify` — held out of the job budget before the worker is admitted,
  and a worker attempt then gets `min(remaining − reserve, 300 s)`: the 300 s is a per-attempt
  cap, and the reserve is not carved out of it. The supporting Git and HTTP calls still have hard
  deadlines pending qualification, so nothing here promises a strict wall-clock budget for every
  individual I/O; the claim is bounded phases plus boundary checks, not a guaranteed stop for
  every blocking call.
- **Cleanup and failure handling.** The primary checkout is fingerprinted before and after
  (HEAD, index, every dirty path with content); any change is `audit_violation`. Workers never
  commit, merge, push or remove worktrees. `<root>/bin/local-worker-archive archive` takes the
  exclusive lock and preserves committed, dirty, untracked, ignored and staged content on a
  recovery ref,
  a verified bundle and a hash-verified archive copy before removing one worktree; its receipt
  goes `prepared` → `archived`. A failure before removal keeps every artifact and the worktree;
  a failure after removal keeps the prepared receipt, ref, bundle and files and needs
  reconciliation.
- **No-change semantics.** `no_changes` exits `10`. `worker_patch_present` is provenance, not a
  diff: the launcher fingerprints each changed-from-base path (content digest plus `lstat` mode,
  missing marker for a deletion) before every worker attempt, attributes a path to an attempt only
  when that state changed, accumulates the fingerprints across attempts, prunes any path whose
  current state no longer matches, and after the final audit reports the flag true only if a
  retained worker-authored path still exists in that state with a non-empty final patch.
  Verification-authored files, reverted worker edits and leftovers from an earlier attempt
  cannot produce `ok`; when verification rewrites a file the worker also wrote, provenance is
  unprovable and the job conservatively reports `no_changes` for parent review. Fingerprints are
  internal and removed before the report is written. Every failure verdict outranks `no_changes`.

## Compatibility blocker

Live steering is unavailable under the required policy on CLI 0.164.0-alpha.11.1: `app-server`
rejects `--ignore-user-config` / `--ignore-rules`, so the launcher cannot start a qualified live
session with the scrubbed configuration it requires. The metadata probe still validates
capability only; it is not a substitute backend. This is an open blocker, not a fixed defect.
