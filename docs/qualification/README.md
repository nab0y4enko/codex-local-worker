# Local Worker qualification records

Current status: [2026-10-25 readiness](2026-10-25-readiness.md), including the actual local-model
results, reviewed fixes, recovery cleanup, and the deferred dashboard desktop gate (Tasks 27-28, future work).

`test_live_qualification.py` is the opt-in, end-to-end suite for the installed launcher. It uses
`bin/local-worker` for every local inference job and records one dated host report from actual
launcher output. Offline unit tests remain under `tests/` and use `python3 -m unittest`.

## Local and read/write pilots

```sh
LOCAL_WORKER_LIVE=1 python3 -m unittest tests.live.test_live_qualification -v
```

The suite writes scratch repositories and launcher state outside the checkout under a temporary
folder. To keep those artifacts for review, set `LOCAL_WORKER_QUALIFICATION_ROOT` to a new
absolute directory. Discovery and the cloud catalog check are read-only; the cloud case constructs
and checks argv but never starts cloud inference unless that capability is explicitly added after
user authorization.

Read jobs retain Codex's native `--output-schema` contract and independently validate every
citation. The live read pilot also checks the retained Codex event stream for a successful
`cat widget.py` tool call whose output contains the cited source line; a schema-valid answer alone
does not qualify as evidence of file inspection. On macOS the model tools use the strict named Codex profile `local_worker_readonly`
with `--strict-config` and a filesystem deny map; read argv omits `sandbox_mode` so the CLI does
not nest Seatbelt sandboxes. The selected worktree is reopened under Codex's `:workspace_roots`
scope beneath the denied launcher-state root, so absolute paths containing glob characters remain
exact workspace roots instead of invalid read globs. State and configured secret denials use
nested exact-path `"." = "deny"` rules, so bracket characters cannot turn those protections into
nonmatching globs. Reports distinguish the native profile from the outer deny wrapper.
Configured stdio MCP servers and their metadata probe run under a read-only Seatbelt profile;
remote HTTP MCP servers are explicitly trusted through the task manifest. Before releasing an
answer, the launcher audits the worktree and withholds the answer if any path changed.

## Optional native pilot

A native run needs a newly created simulator and a generated fixture. Keep both fixtures and
state outside this checkout. The `native` case runs only when all three values are supplied:

- `LOCAL_WORKER_LIVE_NATIVE_PLAN`: version 2 native readiness plan JSON;
- `LOCAL_WORKER_LIVE_NATIVE_SIMULATOR_UDID`: an owned simulator UUID;
- `LOCAL_WORKER_LIVE_NATIVE_TASK`: native write task contract JSON.

Use the helper to create the UIKit/XCUITest fixture and its plan after selecting an available
simulator runtime/device type:

```sh
python3 scripts/prepare_native_live_pilot.py --root /absolute/path/native-pilot \
  --simulator-udid YOUR_OWN_SIMULATOR_UUID
```

Do not use an already booted simulator owned by another job. The helper commits the baseline app
whose label says `Before`; the live write task asks the local worker to change that label to
`After`. The readiness plan selects only `testAppShowsQualificationLabel`, which establishes the
app can launch and captures its screen at baseline and after the change. The separate contract
verification selects only `testAppShowsAfter`, which asserts the accessibility label is exactly
`After`; a successful launch or screenshot cannot substitute for that acceptance assertion. The
launcher performs the gate, verification and before/after screenshot capture.

## Second Mac

The dated host report is intentionally generated by running the suite on that host. Commit the
new report from the second Mac after it runs; never copy or synthesize results from another host.
